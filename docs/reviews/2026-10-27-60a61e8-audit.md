## 1. P2 — Quit skips the latest session when an older autosave is still pending

Locations: [save shortcut](/Users/ketansingrole/git/kchess/apps/desktop/app/utils/library.ts:169), [quit registration](/Users/ketansingrole/git/kchess/apps/desktop/app/utils/library.ts:181).

**Reproduced using the real persistence helper and a delayed storage call.** Start with analysis `*`; change it to `1. e4 *` and let the autosave start; restore `*` before that save answers; call `flushSavedDocuments()`. Quit preparation resolves without waiting for the outstanding save or sending the restored document. Allow that older save to finish: storage now contains `1. e4 *`, although the last document before quitting was `*`.

The helper compares only with the last acknowledged value. It has no queue or in-flight write tracking. Returning to that value is not clean while a different value is being written. This also lets shutdown miss the outcome of that older write. Unlike the previous untouched-window finding, this occurs in one owner after real edits and an undo/reset.

**Fix:** serialize each session's writes, track in-flight and latest desired revisions, and let strict flush wait for all outstanding work before deciding the session is saved. Preserve the latest desired state through failures. Test edit → autosave pending → undo → quit, a failed pending save, and multiple overlapping edits. The probe injects storage delay; it does not measure frequency during normal disk operation.

## 2. P2 — A delayed TV export overwrites newer unsaved analysis

Locations: [initial replacement check](/Users/ketansingrole/git/kchess/apps/desktop/app/composables/useTvPosition.ts:282), [unguarded reply adoption](/Users/ketansingrole/git/kchess/apps/desktop/app/composables/useTvPosition.ts:288), [replacement helper](/Users/ketansingrole/git/kchess/apps/desktop/app/composables/useReplaceAnalysis.ts:13).

**Reproduced with the real analysis store and TV handoff.** With an empty analysis board, open a past TV game and delay its export. Load or enter `1. d4 d5 2. c4 *` on the analysis board while waiting. Deliver the TV export `1. e4 e5 *`: it replaces the newer line without another confirmation and navigates to analysis. An old request can similarly win over a newer selection.

The replacement check runs before the asynchronous download. Neither the load nor its eventual adoption holds an analysis-document revision or a replaceable request identity. The analysis store's study-navigation guard does not protect this caller.

**Fix:** make async analysis handoffs share a request owner and capture the document revision. Discard superseded replies; if the board changed during a still-wanted download, repeat the replacement decision before applying it. Test editing during export, two exports completing in reverse order, navigation away, and opening a study while an export waits.

## 3. P2 — Disconnect cleanup can stop another client's newly started voice recognizer

Locations: [owner release and detached stop](/Users/ketansingrole/git/kchess/crates/kchess-core/src/facade/voice.rs:25), [new owner assignment](/Users/ketansingrole/git/kchess/crates/kchess-core/src/facade/voice.rs:58), [disconnect cleanup](/Users/ketansingrole/git/kchess/crates/kchess-core/src/core.rs:350).

**Reproduced against the real Rust core using its existing fake voice executable.** Client A starts recognition. Disconnect A; immediately start recognition as B and await its successful acknowledgment. B's next valid audio call fails with “Voice input isn’t listening.” The diagnostic uses a single-thread Tokio runtime to make the interleaving deterministic; no microphone or live speech service is needed.

`release_voice` clears the owner synchronously and spawns an unconditional `voice.stop()` for later. B can claim ownership and start before that cleanup reaches the recognizer. The old cleanup then drops B's helper. The recognizer's mutex serializes individual operations but does not bind cleanup to the session it is supposed to release. Window suspension uses this cleanup too.

**Fix:** coordinate owner changes and recognizer operations under one lifecycle queue or generation-aware session owner. The old disconnect's stop must only retire A's session, and B's successful start must guarantee its session remains installed. Test disconnect/start, suspend/start, concurrent starts, and stale audio/finish/stop requests across clients.

## 4. P2 — Another client's preference change assigns drill scores to the wrong duration

Locations: [duration chosen at start](/Users/ketansingrole/git/kchess/apps/desktop/app/composables/useRunLength.ts:36), [record name uses current preference](/Users/ketansingrole/git/kchess/apps/desktop/app/composables/useRunLength.ts:49), [coordinate score save](/Users/ketansingrole/git/kchess/apps/desktop/app/components/CoordinatesTrainer.vue:248), [knight score save](/Users/ketansingrole/git/kchess/apps/desktop/app/components/KnightPath.vue:203).

**Reproduced with a mounted run-length helper and the real shared-preference refresh.** Start a 30-second coordinates run, then deliver another client's saved 300-second preference through `loadViewPreferences()`. The running countdown remains 30 seconds, but `recordVariant('find')` now returns `find-300s`. Both score writers use this live selector when the run ends, so the result goes into the wrong record category. Conversely, a longer run can be filed under a shorter duration and set an unfair personal best.

Disabling the local picker during play does not stop authoritative preference updates from another client or reconnection. `runUntimed` already captures one start-time property; the duration and record identity do not receive the same treatment. The probe verifies the helper/category mismatch; it does not play a complete timed UI run through score storage.

**Fix:** capture duration, mode/level and any eligibility-affecting settings at run start. Use that immutable configuration for the active timer, task rules and persisted result. New shared preferences should apply to the next run. Test external preference refresh during timed and untimed runs and immediately before the finish callback.
