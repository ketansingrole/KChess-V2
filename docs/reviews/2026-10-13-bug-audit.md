# Bug audit — 2026-10-13

Reviewed the current working tree, including the pre-existing uncommitted changes. This is a broad verification and targeted source review, not a guarantee that every defect has been found. No application code was changed by this audit.

## Confirmed findings

### 1. P1 — Rapid chapter navigation can overwrite saved annotations

**Sources:** `apps/desktop/app/stores/analysis.ts:190–198`, `:118–130`; chapter selector at `apps/desktop/app/components/StudyChapters.vue:118`.

`openStudy()` chooses the destination PGN from the renderer's last acknowledged library snapshot. `loadPgn()` starts saving the previous board without waiting for that save, then replaces the tree. If the user edits chapter A, opens B, and returns to A before A's write finishes, A reloads its older PGN. The eventual library response does not reconcile that board. Subsequent edits save the stale tree back over the newer stored chapter.

**Reproduction:** Delay the first study write, edit A, switch A → B → A, resolve the write, edit the reopened A and flush. The final persisted A contains the later edit but has lost the earlier annotation. The focused test fails against the real Rust library backend with only the write response delayed.

**Fix direction:** Make document switches await successful persistence before reading the destination from the updated library. Protect overlapping navigation with a request generation or serialized transition, and retain the current board on failure.

### 2. P1 — A failed study flush still authorizes replacing the edited board

**Sources:** `apps/desktop/app/stores/analysis.ts:232–254`; callers at `apps/desktop/app/components/StudyChapters.vue:32–35` and `:48–50`.

`persistStudy()` catches a rejected write and resolves. `flushStudy()` waits for these resolved writes and the study store's error-recovered queue, then also resolves. Its public callers therefore cannot distinguish successful persistence from a failed save. Add/duplicate chapter actions continue, read the older saved chapter and replace the edited board. `openStudy()` clears the save error, obscuring the loss. The quit callback adds its own unsaved check, but the public flush used by chapter actions does not.

**Reproduction:** Edit an open chapter, reject its `save` commands, call `flushStudy()`, duplicate the chapter successfully, and open the copy, matching the component's action sequence. Flush resolves despite failure; the edited board is replaced by an unannotated copy. Fault injection is limited to study saves; other commands use the real backend.

**Fix direction:** Make the public flush reject or explicitly return failure while its captured document remains unsaved. Callers must stop before replacing the board. Keep background autosave error handling separate so timers do not create unhandled rejections.

### 3. P2 — Review cancellation misses requests waiting for storage

**Sources:** `crates/kchess-core/src/engine/review.rs:367–384`, `:407–421`, `:437–448`.

`request_review()` awaits storage before inserting its job into `state.asked`. `cancel_review(key)` cancels only jobs already queued or running, and does not invalidate a request that is still awaiting storage. When storage returns, the request's global review epoch is unchanged, so it inserts the cancelled job and kicks the review pump.

**Reproduction:** Hold `read_review()`, cancel the requested review key, release storage, then inspect queue status. Waiting is **1**, though it should be **0**. This is a focused Rust integration test of `Reviews`; no engine or network is required.

**Fix direction:** Register pending requests before the first await, or track cancellation generations per review key and recheck them before linking or enqueuing work.

### 4. P2 — An older history lookup replaces the latest game selection

**Source:** `apps/desktop/app/stores/kchess/gameHistory.ts:179–188`.

`openReview()` awaits PGN retrieval and then unconditionally assigns `reviewGame` and navigates to History. It has no request generation or disposal check, unlike the adjacent list and account requests. If opening game A is slow and opening B finishes first, A's late reply replaces B. It can also navigate back after the user has moved away.

**Reproduction:** Hold A's `gamePgn()` response, open B, then resolve A. The selected game changes from B back to A. The focused Vue test fails with `first` instead of the expected `second`.

**Fix direction:** Use a request scope for review opening and invalidate it on replacement, close and owner disposal. Check ownership after PGN retrieval before changing selection or navigation.

## Fix follow-up

The four findings have been implemented in the working tree. Study opening now awaits a strict persistence flush and rejects superseded navigation; a failed flush prevents chapter actions from replacing the edited board. Review requests are registered before asynchronous storage, with cancellation ownership retained until they complete or are dropped. History opening uses `RequestScope`, invalidated by replacement, navigation, closing and disposal.

The original reproduction sources above document the pre-fix behavior. Active regression coverage now lives in:

- `apps/desktop/tests/unit/study-navigation.test.ts`
- `apps/desktop/tests/unit/study-opening.test.ts` (failed duplication and successful retry)
- `apps/desktop/tests/unit/history-selection.test.ts`
- `crates/kchess-core/tests/review-admission.rs`

Post-fix verification passed: all 38 focused TypeScript tests; `pnpm run check` with 95 TypeScript test files / 894 tests, Rust tests and coverage, native/core checks, and performance budgets; `pnpm run build`; and all 49 production Electron E2E tests on macOS Apple Silicon. `pnpm run check:report` was inspected. No installers, tags, releases, or remote changes were made.
