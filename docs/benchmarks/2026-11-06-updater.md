# Updater: download size, speed and restarts (2026-11-06)

How big an update is today, what it could be, and whether KChess can update without a restart.
The plan at the end is worked through in pull requests; tick items off as they land.

## What an update downloads today

Every update downloads the whole installer for its platform (`apps/gpui/src/updates.rs`), for
2026.11.3:

| Package                            | Size   |
| ---------------------------------- | ------ |
| `KChess-…-linux-amd64.deb`         | 134 MB |
| `KChess-…-linux-x86_64.AppImage`   | 129 MB |
| `KChess-…-mac-arm64.zip`           | 118 MB |
| `KChess-…-win-x64.exe`             | 111 MB |

Measured on the published .deb of 2026.11.3 against 2026.11.2 (gzip as packaged; zstd -19; the
delta is zstd with the 2026.11.2 file as its dictionary, long-distance matching on):

| File                 | Unpacked | Changed in 2026.11.3? | Packaged (gzip) | zstd -19 | Delta vs 2026.11.2 |
| -------------------- | -------: | --------------------- | --------------: | -------: | -----------------: |
| `stockfish`          |   103 MB | no                    |           81 MB |    79 MB |                  — |
| `kchess` (the app)   |    66 MB | yes                   |           28 MB |    21 MB |              12 MB |
| `kchess-service`     |    20 MB | yes                   |          8.6 MB |   6.8 MB |             1.7 MB |
| `kchess-cli`         |    20 MB | yes                   |          8.7 MB |   6.9 MB |             1.7 MB |
| `voice/libvosk.so`   |    26 MB | no                    |          7.1 MB |   3.5 MB |                  — |
| `voice/kchess-voice` |   0.5 MB | no                    |          0.2 MB |        — |                  — |
| licences, icons      |   3.2 MB | yes (licences)        |          0.2 MB |        — |                  — |

What this shows:

- **60% of every update is Stockfish, which did not change.** Stockfish (its networks are built in)
  and the voice runtime change only when their pinned versions do, a few times a year.
- Shipping only the files that changed is **≈ 35 MB instead of 134 MB** (-74%).
- Shipping a patch from the previous release's files is **≈ 15 MB** (-89%). An installation
  more than one release behind takes the changed files whole (≈ 35 MB), or the full package.
- `kchess-service` and `kchess-cli` are each 20 MB, mostly the same core linked twice.

macOS and Windows carry the same files in the same proportions (the zip is deflate; the NSIS
installer is already solid LZMA), so the same savings apply.

## Download speed and reliability

- A connection that dropped part way through used to throw the download away and the next try
  started from byte zero: on an unsteady link a 120 MB update might never finish. **Fixed here:**
  the download resumes with `Range` from the bytes it has, up to four times with backoff, and
  starts over only when the server sends the whole file again (`a_dropped_download_resumes_where_it_stopped`).
- A verified download did not outlive the app: each run's download folder was cleared on the next
  start. With **Install on quit** off, or a quit before the download finished, the next start
  downloaded the whole package again. **Fixed:** downloads are kept per version (`.kept/<version>`
  in the private downloads root). A checked package is used again after its digest is checked
  once more, and a `.part` carries on with `Range` from where the last start stopped. A kept part
  that turns out not to be this package's beginning is fetched again whole. Versions up to the
  running one, and any other than the one being downloaded, are removed, except one another KChess
  holds the lock of (`a_download_is_kept_from_one_start_to_the_next`, `old_kept_downloads_are_removed`).
- Progress went to the window once for every chunk the server sent, thousands of redraws for one
  update; it now goes once a megabyte and at the end (`progress_is_reported_a_step_at_a_time`).
  Writes go through a 1 MB buffer on the download's own thread rather than a thread hop per chunk.
- The download is already hashed while it streams, so checking it costs no second read.
- The binaries are already stripped (`.cargo/config.toml`). Stockfish 19, networks built in, is
  103 MB of that; there is nothing to strip from it.

## Updating without a restart

Not for the app itself. KChess is native code: the running process's views and core are
compiled into it, so new code runs only in a new process (this is also why `cargo xtask app
--watch` restarts). What matters is that the restart costs the person nothing:

- **Install on quit** (the default) puts the update in place as KChess quits, so the next start is
  the new version and nobody waits for an install. On macOS the swap is one atomic rename
  (`replace`); the Windows installer runs silently after the app has closed.
- **Restart and install** asks first, names what a restart costs now (a live Lichess clock, a
  puzzle run), and KChess never restarts on its own while you play. Pages open as they were left
  (`viewPreferences`) and unfinished games resume.
- Replacing files under a running app is not safe here: the app starts `kchess-service`,
  Stockfish and the voice helper from its installation folder later on, so a background swap
  would pair the old app with a new core service. Installation stays at quit.
- The helpers alone (Stockfish, the voice runtime) could be swapped while the app runs, but they
  are exactly the parts that almost never change, so this is not worth its risk.

## Plan

1. [x] Resume a dropped download from where it stopped (this change).
2. [x] Keep a verified download across restarts: a per-version folder, re-checked against
   `SHA256SUMS.txt` before use, removed once installed or superseded.
3. [x] Releases publish, beside the unchanged installers and `latest*.yml`, patches from the three
   newest published releases' files (`KChess-<version>-<platform>-<arch>.from-<old>.delta`,
   `cargo xtask deltas`): each file of the new release copied from the installation when its
   SHA-256 matches, a bsdiff patch from the file at its place, or the file whole. New asset names
   only: older updaters see nothing new. Measured in [update patches](2026-11-08-update-patches.md).
4. [x] The updater downloads the patch for its version, rebuilds the release from the installed
   files, checks each against the patch's digests, and stages it as the whole package's
   download: any mismatch falls back to the full package (`apps/gpui/src/updates/patch.rs`).
   - macOS: the new bundle, signature-checked as today (`signed_alike`), then the same atomic swap.
   - AppImage: one file, patched from the installed AppImage.
   - Windows: the release's update installer (its installer without the files) writes the
     rebuilt files beside it, with the same uninstall entry, shortcuts and uninstaller.
   - .deb: a `.deb` of the rebuilt files with the release's control archive, through dpkg as
     before.
5. [ ] Find out how much of `kchess-service` and `kchess-cli` one shared binary could save
   (≈ 7 MB of every full download, 20 MB installed), keeping both commands' names.
6. [ ] Check for updates with `If-None-Match`: an unchanged answer does not count against GitHub's
   unauthenticated rate limit (60 requests an hour per address).
